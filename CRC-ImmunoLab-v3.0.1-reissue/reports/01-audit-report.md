# CRC ImmunoLab 3.0 代码审计报告

## 一、结论摘要

- 原项目能否构建：**能**。主 TypeScript、批量 Worker、现有构建脚本和原有浏览器 smoke test 均可运行。
- 原项目能否运行：**能**。没有发现阻断启动或核心页面白屏的问题。
- 阻断问题：**0 项**。
- 高风险问题：**4 项**，集中在统计结论、时间轴、导入安全和项目恢复。
- 中风险问题：**6 项**，集中在空间 Worker 生命周期、导入边界、构建可重复性、治疗日程编辑和分析一致性。
- 低风险/建议项：**3 项**，包括空间指标命名、安全响应头和可访问性。
- 本次处理：用户已明确授权推荐修改，因此实施了“必须修复”和“建议本次修复”，并纳入低风险且改动很小的安全/可访问性修复。
- ⚠️ 算法行为变化：修正随机种子配对、第 0 天给药和时间轴后，同一配置在 3.0.1 中可能得到与 3.0.0 不同的数值结果。这是必要的正确性修复。

- 尚未验证：实际 Cloudflare 项目设置、线上响应头、Git 分支/提交历史、GitHub Actions、生产域名 OPFS 跨会话恢复。

## 二、优先问题

1. **P01：所谓“配对随机种子”实际未配对，影响治疗臂比较。**
2. **P02：第 0 天给药被遗漏，时间序列第 0 天也不是未处理基线。**
3. **P03：导入文件中的文本可进入 `innerHTML`，存在 DOM XSS 风险。**
4. **P04：OPFS 最近项目索引依赖 LocalStorage，隐私/受限环境可能无法恢复。**
5. **P05：空间 Worker 和监听器生命周期未释放，重复进入页面会积累资源。**

## 三、问题明细

### P01：治疗臂比较未使用真正的配对种子

- 严重程度：高
- 结论状态：已确认
- 位置：`src/worker/batch.worker.ts` 原 57–60 行；`aggregate()` 原 48–55 行
- 现象：种子公式包含全局 `completed`，不同治疗臂的同一 replicate 获得不同种子；聚合却按数组位置当作配对样本比较。
- 影响：“优于对照概率”混入不同随机扰动，降低治疗臂比较的可解释性，且与界面“配对种子”说明不一致。
- 证据：原版 replicate 1 的四个治疗臂种子分别为 `20260804`、`20324156`、`20387508`、`20450860`；自动复现结果见 `original-reproduction.json`。
- 建议：同一 replicate index 在所有治疗臂和扫描点使用相同基础种子；聚合按 replicate ID 显式匹配。
- 替代方案：使用预生成随机扰动表；更严格，但改动更大。
- 改动范围：中
- 是否改变界面或行为：⚠️ 是，统计数值会改变，界面结构不变。
- 是否需要用户单独批准：用户已总体批准推荐修改。

### P02：第 0 天给药遗漏，时间轴偏移

- 严重程度：高
- 结论状态：已确认
- 位置：`src/worker/batch.worker.ts` 原 `doseAt()` 与 `runOne()`
- 现象：给药条件使用 `day < administrationDay`，当起始日为 0 时永远不命中；循环先更新再记录，标记为第 0 天的数据其实已推进 0.25 天；循环还会在终点日再执行一次更新。
- 影响：三联方案中第 0 天基质调节不起作用；初始值和终点含义与文档不一致；所有轨迹存在时间轴偏移。
- 证据：原版第 0 天肿瘤负荷为 `1.004972...`，不是 1；三联治疗第 1 天药物暴露为 0。
- 建议：先记录第 0 天，再按半开区间 `[t, t+dt)` 处理给药；到达终点时停止更新。
- 替代方案：保留旧时间轴并仅修第 0 天给药，不建议，因为基线定义仍错误。
- 改动范围：中
- 是否改变界面或行为：⚠️ 是，模型轨迹和历史结果会改变。
- 是否需要用户单独批准：用户已总体批准推荐修改。

### P03：导入数据可能触发 DOM XSS

- 严重程度：高
- 结论状态：已确认
- 位置：`src/app.ts` 多个 `innerHTML` 模板；原 `importProject()`
- 现象：导入 JSON 的项目名、研究名、治疗臂名称、诊断文本等没有结构校验或上下文输出编码，随后进入 `innerHTML`。
- 影响：打开未知来源的研究包可能执行页面脚本、篡改界面或读取同来源本地数据。
- 证据：明确代码路径为“文件 JSON → 直接赋给 project → 模板字符串 → innerHTML”。OWASP 将不可信数据写入 `innerHTML` 视为客户端 XSS 高风险模式。
- 建议：导入时归一化白名单字段、限制长度和范围；所有动态文本输出编码；Toast 使用 `textContent`；独立报告同样编码并设置 CSP。
- 替代方案：全面改用 DOM 节点构建或 Trusted Types；更强，但本次会造成大规模重构。
- 改动范围：中
- 是否改变界面或行为：否；恶意/异常输入会被拒绝或截断。
- 是否需要用户单独批准：否，属于安全修复。

### P04：OPFS 最近项目恢复依赖 LocalStorage

- 严重程度：高
- 结论状态：已确认
- 位置：`src/storage/store.ts` 原 34–37 行
- 现象：项目主体写入 OPFS，但“最近项目 ID”只写入 LocalStorage；若 LocalStorage 被禁用，下一次打开无法定位 OPFS 中已有项目。
- 影响：用户可能误以为项目丢失；隐私模式或严格浏览器设置下尤其明显。
- 证据：原 `saveProject()` 调用 `safeSet('crc3:lastProject')`，原 `loadLastProject()` 也只读取该键。
- 建议：在 OPFS 中保存 `index.json`；写入失败时统一降级；回退存储使用一致的项目和索引写入。
- 替代方案：启动时枚举 OPFS 所有项目并按更新时间选择；可恢复更多项目，但实现和迁移更复杂。
- 改动范围：中
- 是否改变界面或行为：否；只提高恢复可靠性。
- 是否需要用户单独批准：否。

### P05：空间 Worker、Blob URL 和监听器未释放

- 严重程度：中
- 结论状态：已确认
- 位置：`src/ui/spatial.ts` 原 7–18 行；`src/app.ts` 原 `renderSpatial()`
- 现象：每次进入空间页创建新实例和 resize 监听；内嵌 Worker 的 Blob URL 不回收；离开页面不终止 Worker；固定 `setInterval` 不等待上一帧完成。
- 影响：重复导航后可能出现后台计算、内存增长、重复渲染和 Worker 消息队列积压。
- 证据：原类没有 `destroy()`；监听使用匿名函数无法移除；Blob URL 未保存；步进每 70 ms 无在途控制。
- 建议：实现 `destroy()`，释放 Worker/URL/监听/计时器；一次只允许一个 step 在途；复用离屏 Canvas。
- 替代方案：空间工作区保持单例永不重建；可行，但需要调整页面状态管理。
- 改动范围：中
- 是否改变界面或行为：否；后台资源使用更稳定。
- 是否需要用户单独批准：否。

### P06：导入文件没有架构、大小和运行规模限制

- 严重程度：中
- 结论状态：已确认
- 位置：原 `src/app.ts importProject()`
- 现象：任意 JSON 只要含 `config` 和 `studies` 即被接受；没有文件大小、数组长度、数值范围或运行数限制；单项导出研究反而不能重新导入。
- 影响：畸形文件可造成冻结、内存压力、错误状态或不可逆的项目替换；导入/导出格式不对称。
- 建议：增加 25 MB 上限、白名单和范围归一化、总运行上限、单研究往返支持，并重新计算摘要。
- 替代方案：引入 JSON Schema/Ajv；更标准，但会增加依赖和单文件体积。
- 改动范围：中
- 是否改变界面或行为：是，异常输入会被拒绝或标准化。
- 是否需要用户单独批准：否。

### P07：首次给药日显示错误并破坏错峰计划

- 严重程度：中
- 结论状态：已确认
- 位置：原 `src/app.ts armCard()` 与治疗日程变更逻辑
- 现象：`Math.min(...starts.concat([0]))` 使显示值总是 0；修改时把所有启用治疗设置为同一日期，丢失化疗与 PD-1 的原始 2 天偏移。
- 影响：用户看到的计划与实际配置不一致，调整联合方案会意外改变机制。
- 建议：显示真正最早启用治疗日；修改时整体平移所有启用日程，保留相对偏移。
- 替代方案：分别暴露每种治疗的起始日；控制更细，但会增加界面复杂度。
- 改动范围：小
- 是否改变界面或行为：是，修复后的输入值和编辑行为符合配置。
- 是否需要用户单独批准：否。

### P08：分析 KPI 可能引用不同治疗臂

- 严重程度：中
- 结论状态：已确认
- 位置：原 `src/app.ts renderAnalysis()`

- 改动范围：小

### P09：空间“免疫排斥指数”命名过度

- 严重程度：低

- 位置：原 `src/ui/spatial.ts updateSelectionMetrics()`

- 改动范围：小

### P10：构建链路不能从源码完整重现

- 严重程度：中
- 结论状态：已确认
- 位置：项目结构、`tsconfig.worker.json`、`tools/build_standalone.py`
- 现象：`dist/spatial.worker.js` 没有对应 `src` 源文件；原构建命令不会生成它；单文件构建使用静默字符串替换，即使模板变化也可能产出不完整文件。
- 影响：清理 `dist/` 后无法完整重建；后续维护者可能修改了构建产物却没有规范源；失败可能在运行时才暴露。
- 建议：加入规范空间 Worker 源文件、统一构建脚本和替换点断言；固定 TypeScript 开发版本声明。
- 替代方案：将空间 Worker 完全迁移到 TypeScript；更理想但超出本次最小修复范围。
- 改动范围：中
- 是否改变界面或行为：否。
- 是否需要用户单独批准：否。

### P11：缺少部署安全响应头和 CSP

- 严重程度：低
- 结论状态：已确认
- 位置：项目根目录和 `index.html`
- 现象：原项目没有 `_headers`、CSP、点击劫持保护或权限策略。
- 影响：即使修复输出编码，浏览器仍缺少第二层防护；页面可被嵌入第三方 frame。
- 建议：为 Cloudflare Pages 添加 `_headers`；源码页添加兼容离线模式的 meta CSP；Blob Worker 明确加入 `worker-src blob:`。
- 替代方案：仅线上配置 Cloudflare Transform Rules；会使安全配置脱离代码仓库。
- 改动范围：小
- 是否改变界面或行为：否；不受允许列表支持的未来资源会被阻止。
- 是否需要用户单独批准：否。

- 建议：补充 `for`、`aria-label`、`role=status`、焦点样式和减少动态效果支持。
- 替代方案：完整 WCAG 审计；建议后续在真实浏览器和读屏器中执行。
- 改动范围：小
- 是否改变界面或行为：轻微可见焦点变化。
- 是否需要用户单独批准：否。
